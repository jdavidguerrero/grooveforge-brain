## Theory

### DCO vs VCO — la diferencia que define el sonido del Juno

Un VCO (Voltage-Controlled Oscillator) analógico genera su onda usando un capacitor
que carga y descarga libremente, controlado por un voltaje. El problema: el capacitor
es sensible a la temperatura. A medida que el circuito calienta, la frecuencia deriva
(thermal drift). En un Moog de 3 VCOs, cada uno deriva de manera diferente — ese
"beating" orgánico e involuntario entre voces es exactamente lo que da el warmth del Moog.

El DCO (Digitally-Controlled Oscillator), introducido por Roland en 1982, resuelve el
drift con un truco elegante: un contador digital lleva el tiempo, y dispara la descarga
del capacitor en intervalos exactos. La frecuencia es digitalmente precisa, pero la
forma de onda resultante sigue siendo analógica — el capacitor carga y descarga como
siempre. Resultado: afinación estable y reproducible, sin beating involuntario entre
voces.

En nuestra implementación con `AudioSynthWaveform`, ya tenemos un "DCO perfecto":
frecuencia fija por software, forma de onda digital. No hay drift, no hay thermal
compensation necesaria.

### Por qué el Juno suena "hi-fi" vs el Moog "warm"

| Característica | Moog Minimoog | Roland Juno-106 |
|---|---|---|
| Oscilador | VCO — drift térmico → beating orgánico | DCO — estable, sin drift |
| Filtro | Ladder 4-polo (24dB/oct), saturación rica | IR3109 2-polo (12dB/oct), más limpio |
| Envelopes | 2 ADSR independientes (VCF + VCA) | 1 ADSR compartido |
| Movimiento | Orgánico por imperfecciones del hardware | Artificial via BBD chorus |
| Resultado | Warm, orgánico, impredecible | Clean, lush, controlado |

El Moog suena "vivo" porque sus imperfecciones son parte del diseño.
El Juno suena "moderno" porque es preciso, y compensa esa precisión con el chorus.

### Arquitectura de señal del Juno-106

```
DCO (saw/square/pulse) ──┐
Sub (square, /2)        ──┤──→ Mixer ──→ VCF (LP 12dB) ──→ VCA ──→ Chorus ──→ Out L/R
Noise                   ──┘              ↑                    ↑
                                      (ADSR)               (ADSR)
                                   cutoff mod          amplitude
```

Un solo envelope ADSR modula simultáneamente:
1. El VCF: desplaza el cutoff hacia arriba (attack → decay → sustain) y lo cierra (release)
2. El VCA: controla la amplitud de forma sample-accurate via `AudioEffectEnvelope`

Esta diferencia con el Moog (2 envelopes independientes) es una simplificación de
hardware que define el carácter del Juno: el filtro y el volumen siempre "respiran"
juntos.

### BBD Chorus — cómo funciona el efecto que define el Juno

Un Bucket Brigade Device (BBD) es un circuito analógico formado por capacitores en
cascada. La señal de audio se transfiere de capacitor en capacitor a una velocidad
controlada por un clock externo — como una brigada pasando cubetas de agua.

Si el clock es constante → delay fijo.
Si el clock varía (controlado por un LFO) → el tiempo de delay varía → vibrato/chorus.

La mezcla 50/50 de la señal dry con la señal delayed+modulated crea el chorus:
- La señal original mantiene el tono base
- La señal delayed tiene su pitch levemente desplazado por el Doppler del delay variable
- La mezcla produce el efecto de dos voces ligeramente desfasadas → chorus

El desfase entre canal L y R (LFO en cuadratura — 90° de diferencia) crea la imagen
estéreo ancha característica del Juno.

**Modos del Juno-106:**
- Modo I: LFO ~0.5Hz, depth sutil — ideal para strings, pads, texturas largas
- Modo II: LFO ~1.0Hz, depth pronunciado — ideal para bass, lead, plucks

En la Teensy Audio Library, `AudioEffectChorus` implementa este principio digitalmente:
un delay line circular (buffer de shorts en RAM) + interpolación entre muestras.

**API real de `AudioEffectChorus`:**
```cpp
// El buffer de delay es externo — el usuario lo declara en static RAM
static short chorus_buf[CHORUS_DELAY_LENGTH];
chorus.begin(chorus_buf, CHORUS_DELAY_LENGTH, n_voices);
// n_voices: número de voces del chorus (1-N)
// CHORUS_DELAY_LENGTH: longitud del buffer en shorts
```

El buffer debe vivir en el scope del objeto (static o miembro del owner) para no
ser liberado mientras el chorus esté activo.

### Cálculo de AudioMemory para el Juno-106

Cada bloque de la Teensy Audio Library = 256 bytes = 128 muestras @ 16-bit.

| Nodo en el grafo | Bloques estimados |
|---|---|
| _dco | 1 |
| _sub | 1 |
| _noise | 1 |
| _mixer | 1 |
| _vcf | 1 |
| _vcaEnv | 1 |
| _chorus | 2 (input + output) |
| _dryWetMix | 1 |
| _out (L+R) | 2 |
| Buffer de seguridad | 13 |
| **Total** | **24** |

24 bloques × 256 bytes = 6.144 KB — dentro del budget de ~400KB.

### Grafo de audio

```
_dco   ──(c1)──→ _mixer ch0 (0.6)
_sub   ──(c2)──→ _mixer ch1 (0.3)   ──(c4)──→ _vcf ──(c5)──→ _vcaEnv ──(c6)──→ _dryWetMix ch0 (dry)
_noise ──(c3)──→ _mixer ch2 (0.0)                                      ──(c7)──→ _chorus ──(c8)──→ _dryWetMix ch1 (wet)
                                                                                          _dryWetMix ──(c9)──→ _out L
                                                                                                     ──(c10)──→ _out R
```

### Decisión clave: buffer del chorus en el objeto

`AudioEffectChorus::begin()` recibe un puntero a un buffer de shorts que el llamador
debe mantener vivo. Se declara como miembro `_chorusBuf[JUNO_CHORUS_BUF_LEN]` en el
header para garantizar que vive mientras el objeto Juno106 exista. No usar stack local
ni heap — ambos son riesgosos en el audio path del Teensy.

### Decisión: dry/wet como AudioMixer4, no como gain directo del chorus

El chorus BBD analógico mezcla internamente dry+wet. La implementación digital
(`AudioEffectChorus`) solo produce el path wet. Por eso se necesita un `AudioMixer4`
para la mezcla. Esto permite:
- Bypass limpio (ch1 gain = 0.0, ch0 gain = 1.0)
- Modo I y Modo II con diferentes ratios de wet
- Futuro: crossfade suave entre modos

ser claramente audible al activarse — imagen estéreo ancha, movimiento característico.

### Cómo reproducirlo

```bash
cd /Users/juandavidguerrerocastro/GROOVEFORGE/grooveforge-brain/apps/firmware-teensy
~/.platformio/penv/bin/pio run -e sketch -t upload
~/.platformio/penv/bin/pio device monitor -b 115200
```

Secuencia de prueba en el monitor serial:
```
n69        → A4, sawtooth + chorus modo I (default)
c1         → chorus modo I (sutil, 0.5Hz)
c2         → chorus modo II (pronunciado, 1.0Hz)
c0         → chorus off (comparar sonido dry)
c1200      → filter cutoff 1200 Hz
wS         → waveform sawtooth
wQ         → waveform square
f          → noteOff
```
